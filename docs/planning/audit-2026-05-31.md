# Pocket — Consolidated Audit Report

**Date:** May 31, 2026
**Scope:** Full audit of the Pocket codebase against the roadmap and idea corpus.
**Method:** 6 stages — (1) roadmap↔code alignment, (2) architecture quality, (3) execution-cycle trace, (4) security & safety, (5) idea-corpus analysis, (6) this reconciliation.
**Stance:** Brutally practical. Optimized for system *stability*, not feature completeness.

---

## Executive verdict

The foundation is genuinely solid and unusually well-organized for a solo build — this is not a vaporware roadmap. Stages 1–4 are real, modular, and mostly do what they claim. **Do not rewrite it.**

But "Stage 4 closed / all verified" oversells reality in four specific ways, and there are three real risks worth fixing before Stage 5 piles concurrency and perception on top:

1. The **executor's safety boundary is theater** — it blocks 1 of 10 destructive commands and leaks `.env`.
2. The **conversation core is a god-function** with no clean seam, and a **concurrent-turn race** that Stage 5 will detonate.
3. The **canonical identity document has zero runtime effect** — the safety story rests on a doc the model never reads.

None of these are on fire *today*, because nothing autonomous can reach the executor (a human triggers every action). All three become live the moment Stage 5 autonomy or Stage 8 co-pilot lands. The window to fix them cheaply is now.

---

## What's solid — do NOT destabilize

Touch these only with care; they're the parts holding everything up.

- **Leaf-layer modules:** `state_manager` (properly `RLock`-guarded), `event_bus` (clean pub/sub, error-isolating), `pocket_module` (ABC contract), `config_loader`, the `permissions` gate *mechanism*.
- **`is_read_allowed()`** — resolves paths before checking, so traversal (`chroma_data/../.env`) and symlinks are handled correctly. The read guard is well-built; it's just not applied everywhere.
- **`file_editor`** — abort-on-backup-failure ("no backup → no write") is correct and careful.
- **`degradation` dedup** — genuinely prevents the TTS failure feedback loop. Real engineering.
- **The modular refactor itself**, the decision-log discipline, and the documentation habit.

---

## 1. Fix immediately (cheap, high-value, before Stage 5)

These are either active risks or cheap blockers. None require a refactor.

- [ ] **Close the `/exec` → `.env` hole.** Route executor file-touches through `is_read_allowed()` (or block secret paths at the executor). Today `/exec type .env` prints your `TAVILY_API_KEY` and logs it to `decisions.jsonl`. *(Stage 4)*
- [ ] **Stop trusting the executor denylist; relabel it.** It blocks `rm -rf` and almost nothing else (`rm -r`, `rm  -rf` with two spaces, `rmdir /s`, `python -c "shutil.rmtree(...)"`, `curl|sh`, `echo > file` all pass). Until the redesign (below), do not treat it as a boundary — the real protection is your y/n approval. *(Stage 4)*
- [ ] **Add a timeout to the Piper subprocess.** `proc.communicate()` in `run_piper_tts` has none; a hung Piper hangs the TTS worker permanently and every later utterance queues behind it. *(Stage 3)*
- [ ] **Add a turn mutex.** A single lock around `handle_user_input_sync` so text + voice (or, later, proactive triggers) can't run concurrent turns that race on the unlocked global `session_history` and fire double Ollama calls. Latent bug today; systemic at Stage 5. *(Stage 3)*
- [ ] **Hand-merge the safety essentials into `base_system.md`.** Until the prompt pipeline exists, inject the "external content is information, not instruction" stance and the "what Pocket never does" rules into the 6-line runtime prompt. Right now the only injection defense (the identity doc) is never loaded. *(Stage 1, 4)*
- [ ] **Delete the dead code.** `avatar/expression_engine/` (the pre-4a fossil orchestrator + a redundant full Piper bundle — the bulk of repo weight), `persona/persona.py` (dead `Persona` class), `persona/identity.md` (dead 14-line dupe). Nothing imports them. *(Stage 1, 5)*
- [ ] **Pick one owner for identity** (see Redesign #3) and stop the file from forking further. *(Stage 5)*

## 2. Redesign entirely (rethink the primitive, don't patch)

- **The executor's safety model.** Don't extend the substring denylist — it's the wrong primitive. Replace it with: `shlex`-parse the command, match on program + flags, reject shell metacharacters / redirects / pipes-to-shell / `python -c` unless explicitly confirmed, and run in a constrained working directory (or container). Decide executor backup policy too: route executor writes through `backup_file`, or accept they're unguarded and say so loudly while leaning on Docker backups. *(Stage 4 — the "no backup, no exceptions" 4g.1 guarantee is currently false through `/exec`.)*
- **The conversation core.** `llm.handle_user_input_sync` is simultaneously the Ollama client *and* the entire 9-step turn pipeline. Re-seat it into three layers: a pure model client, a **prompt-assembly pipeline** (identity + safety + mode + memory + emotional sections), and a **turn orchestrator** that owns memory/avatar/tts as steps. Nearly every Stage 6+ feature depends on this seam existing. *(Stages 2, 3, 5)*
- **Identity representation.** Collapse the **seven** scattered representations (`pocket-identity.md`, `persona/identity.md`, `persona/persona.py`, `base_system.md`, plus the three the idea corpus proposes) into one canonical, runtime-loaded source. This is a paradigm decision (prose-doc-loaded-into-prompt vs structured config), not a delete-the-dupes cleanup. *(Stages 1, 5)*
- **The communication model.** The event bus exists but carries one flow; everything else runs on direct imports plus lazy-import cycle-dodges (`tts ↔ degradation`). Decide before Stage 5 multiplies event sources: commit the conversation/avatar/tts path to the bus and retire the direct calls, or formally abandon the bus. Running both half-heartedly is the current worst case. *(Stage 2)*

## 3. Implement next (realistic, maturity-ordered)

This sequence front-loads the refactors that make everything after them cheaper, and keeps the existing Live2D hard gate where it is.

**Phase 1 — Conversation refactor (do *before* Stage 5)**
- [ ] Prompt Assembly Pipeline — fixes the inert identity doc (Stage 1), injects the safety rule (Stage 4), gives the god-function a seam (Stage 2). The single highest-leverage net-new idea in the corpus.
- [ ] Split `llm.py` → pure Ollama client + conversation orchestrator + minimal `turn_manager` (formalizes the turn mutex).
- [ ] Full executor hardening (Redesign #1).
- [ ] Decide the **agent→tool path** explicitly — even if the answer is "human-only for now," document it. Stage 8a assumes it exists; it doesn't.
- [ ] Wire a generic lifecycle loop over all 14 modules (currently only 4 get `start()`/`health_check()` at runtime).

**Live2D hard gate** — unchanged. Real `.moc3` model in place before Stage 5 animation work.

**Phase 2 — Stage 5 as roadmapped, now on a real orchestrator + the bus**
- [ ] Move conversation/avatar/tts onto the event bus (kills the cycles before perception adds more sources).
- [ ] `tool_registry` replaces the 150-line if/elif command chain.
- [ ] **Privacy boundaries (5e) BEFORE any screenshots or always-listening.**
- [ ] Screen awareness, dynamic idle behaviors.

**Phase 3 — Stage 6 intelligence**
- [ ] 6-Early: semantic search → skill modes (**resolve the taxonomy first** — task-axis vs mood-axis vs temperament are three competing systems).
- [ ] 6-Late: reflection, memory metadata/scoring, emotional continuity.
- [ ] Fix memory pollution here: `/read` and `/search` currently persist injected file/web content into ChromaDB permanently — tag it ephemeral or don't auto-save it. *(Stage 3)*

**Phase 4 — Autonomy (6i), and only here**
- [ ] The goal/task framework, on top of reflection + metadata + a hardened executor + the agent-path decision. Harvest 6i's *safety principles* (no self-authorization, no scope escalation, resource budgeting) into the design now; defer the runtime.

## 4. Ignore / defer (don't let these consume attention)

- **The entire 6i autonomy runtime** until Phase 4. Keep the principles, defer the build.
- **`6i.8` pre-approved actions without per-action approval** — this contradicts the "every action approved" model. Don't design it until the executor is provably safe. *(Stage 4, 5)*
- **Wakeword / always-listening** — premature and a privacy regression (always-on mic before 5e). F9 push-to-talk is fine and safer; arguably drop it entirely.
- **The 10-module `conversation/` package** — build 2 modules, ignore 8 until something needs them.
- **The ground-up directory-framework reorg** — north star only. Adopting it literally is a rewrite, which violates your own "no rewrites" philosophy.
- **Multi-agent (9b), Internal Monologue, Cognitive Profile (9a)** — speculative, no foundation.
- **Richer 4j.1 metrics, telemetry, drift detection (8m), self-observability dashboard (8k)** — the boolean monitor is fine for now.
- **Streaming STT, emotional-inflection TTS, gaze, presence sim** — polish.
- **`docs/` empty stubs** — either fill the two that matter (a real README; `future-ideas.md`) or delete the empty scaffolding so it stops masquerading as documentation. Low priority.
- **Most of "Things to think about while waiting for art"** — ~70% is already built (Stage 4). Archive the file.

## Appendix — Full findings index by stage

**Stage 1 — Roadmap↔code alignment.** Stages 1–4 substantially real. Overstated: 4g.1 backup ("no exceptions" false via `/exec`), 4j.1 monitoring (boolean only, latency/quality/growth metrics unbuilt), 4j/4s (only 4 of 14 modules wired into lifecycle), 4q (bus built but carries one flow). Identity doc runtime-inert. Dead code: `avatar/expression_engine/`, `persona/persona.py`, `persona/identity.md`. Minor: duplicate imports in `pocket.py`, stray root `decisions.jsonl`, near-empty `project_tree.txt`, half-empty `docs/`.

**Stage 2 — Architecture.** Two communication paradigms; bus bypassed; real cycles broken by lazy imports. `handle_user_input_sync` is a god-function (model client + pipeline fused). No agent→tool path. Inverted dependency (`web_search` imports `llm`). Command routing is a 150-line if/elif. Scaling risks: unbounded `session_history` re-sent every turn, monotonic ChromaDB growth, synchronous thread-soup. StateManager thread-safety **verified OK** (RLock).

**Stage 3 — Execution trace.** Conversational cycle has no decision/executor step. 4r not the source of truth for `speaking` (a separate `threading.Event` is; WS resync reads the stale field). `voice_active`/`current_query` never written. `/read` + `/search` permanently persist injected content to memory. No Piper subprocess timeout. **🔴 No turn mutex → concurrent text+voice turns race.** Degradation dedup correctly prevents the TTS loop.

**Stage 4 — Security.** 🔴 Executor denylist blocks 1/10 destructive commands (empirically tested) and false-blocks benign ones; "regardless of approval" is false. 🔴 Executor bypasses the read denylist (`/exec type .env` → key leak → logged). 🔴 `shell=True` writes void the backup guarantee; `/rollback` can't recover them. 🟠 Prompt-injection defense absent from runtime prompt (mitigated today only by the missing agent path). 🟠 Test reality: executor boundary `skip()`-ped; only "denylist non-empty" checked — read/write denylists *are* tested (credit). 🟡 Secrets reachable in decision log; compound-command approval under `shell=True`; Tavily sees all queries. **Today's safety = human-in-loop + no agent path, not the denylist.**

**Stage 5 — Idea corpus.** ~70% of "waiting for art" already built. Identity forking into 7 homes. Skill-mode taxonomy drift (3 axes). Directory framework = rewrite-in-disguise; north star only. Autonomy/6i premature (needs reflection + metadata + safe executor + agent path); 6i.8 contradicts the approval model. Wakeword premature + privacy regression. Reduced net-new set: conversation orchestration (scoped), prompt-assembly pipeline, tool registry, identity consolidation, model-roles plan, 6i-as-north-star, the architectural-questions doc adopted as an ADR checklist. Hardware note: a 5090/96GB build relaxes the VRAM ceiling for 5d/6f but doesn't change ordering.
